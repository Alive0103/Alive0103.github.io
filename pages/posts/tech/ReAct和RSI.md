RSI（Recursive Self-Improvement，递归自我改进）大概是今年 Agent 圈最热的词。2025 年 Darwin Gödel Machine 的论文发布之后，"会自己改进自己的 AI"突然从科幻设定变成了可以跑实验的东西；进入 2026 年，几乎每周都有新工作声称自己的系统具备"自我改进"能力。

但读了一批论文和讨论之后，我越来越觉得这个词正在被稀释。模型失败后重试一次，叫自我改进；把一段报错反思写进提示词，叫自我改进；改写自己的代码、通过基准验证、让下一代继承这个改动，也叫自我改进。这三件事的难度、风险和意义完全不同，却共用同一个名字。

这篇文章想做两件事：一是把从 ReAct 到 RSI 这条线上的几个关键工作放回各自的位置，二是给出我自己的判断——什么才配叫"自我改进"。

我的主线是三个问题：**改了什么？由谁验证？下一轮是否继承改动？** 用这三个问题去量，很多被称为 RSI 的东西会立刻现出原形。

## ReAct 到底做了什么

先把起点说清楚。2022 年的 [ReAct 论文](https://arxiv.org/abs/2210.03629)（Yao 等）做的事情，今天看已经很朴素：让语言模型在解决任务时，交替产生推理轨迹（Thought）和动作（Action），动作作用于外部环境，环境返回观察（Observation），再进入下一轮推理。

这个设计的价值在于把推理过程外化成了文本。在纯 CoT（思维链）里，模型从头到尾闭门推理，中间任何一个事实错误都会污染后面的所有步骤；而在 ReAct 里，推理可以基于环境刚返回的真实观察随时修正——查到的页面不存在，就换一个关键词；上一步动作失败，就在下一段 Thought 里分析原因。在 HotpotQA、FEVER 这类知识问答任务上，以及 ALFWorld、WebShop 这类交互环境上，这种交替结构都明显超过了单纯的推理或单纯的动作序列。

但我想强调的是 ReAct 的边界，因为后面所有的混淆都从这里开始。

**ReAct 的循环只发生在一次任务之内。** 循环里确实有什么东西在"变"：上下文越来越长，模型对当前任务的估计越来越准，轨迹越来越接近答案。但任务结束的那一刻，这些 Thought 和 Observation 全部随上下文丢弃。下一次任务到来时，Agent 还是那个 Agent——同样的权重，同样的代码，同样的提示词。它在这任务里"学到"的一切，都不会被带到下一个任务。

![ReAct：单次任务的推理—行动—观察循环](/images/posts/react-rsi/react-loop.svg)

所以 ReAct 改变的是**任务内的轨迹**，不是 Agent 本身。把它叫做"自我改进"，就像把一个人在考场上打草稿叫做"这个人变聪明了"——草稿确实帮助了这一场考试，但交卷之后就被收走了。

这个区分听起来像是咬文嚼字，但它直接决定了我们怎么评价后面那些工作。

## 反思算不算自我改进

ReAct 之后，最先模糊这条边界的是 [Reflexion](https://arxiv.org/abs/2303.11366)（Shinn 等，2023）。

Reflexion 在 ReAct 的循环外面又包了一层：一次尝试失败后，模型生成一段语言化的反思——"我刚才错在假设了 X，其实应该先验证 Y"——把这段反思存进一个情景记忆（episodic memory）里，下一次尝试同一个任务时带上它。如此反复，直到通过。作者称之为"语言化的强化学习"：不更新权重，用文本充当梯度的角色。

它比 ReAct 多走了一步：失败经验不再只是上下文里堆着的原始观察，而是被显式压缩成了一句教训。这一步是真实有效的，在 HumanEval、ALFWorld 等基准上都有可观的提升。

但注意记忆的寿命。Reflexion 的反思在同一个任务的多次尝试之间保留，任务一换，记忆清空。它的"改进"依然是**一次任务中的改进**：同一个编程题，第五次尝试确实比第一次强，但换一道题，Agent 还是从零开始。权重没变，代码没变，提示词模板没变。

再往外走一步，是 [STOP](https://arxiv.org/abs/2310.02351)（Self-Taught Optimizer，Zelikman 等，2023）。STOP 的思路更激进：写一段"用模型改进方案"的脚手架代码，然后让模型去改进这段脚手架代码本身，递归下去。比如先让模型优化一个数学题的解法，再让模型优化"优化解法的那段提示词和代码"，并可以把这个改进器应用到改进器自己身上。

STOP 已经开始摸到另一条边界：它改的东西——脚手架代码——**在运行结束后是留得下来的**，而且改得好不好，由下游任务上的真实性能来裁决，不是模型自己说了算。

到这里，我想把"中间地带"的划分说清楚：

- **一次任务中的反思**：改动只存在于上下文或任务级的记忆里，任务结束即失效。ReAct、Reflexion 都在这一层。
- **可保留的系统改进**：改动落在代码、提示词、工具配置这些持久化的系统组成部分上，经过外部验证后被保留，下一次运行的是一个新版本的系统。

中间这一层恰恰是最混乱的地方。2026 年的很多讨论里，只要 Agent 在失败后说了几句反思、或者把什么写进了上下文，就被贴上 self-improvement 的标签。按上面的划分，这些大多只是把 ReAct 的上下文管理做得更好。**把每一次重试都叫自我改进，这个词就什么都不剩了。**

## 真正的 RSI 长什么样

RSI 这个概念在理论上有一个非常严肃的源头：Schmidhuber 2003 年提出的 Gödel Machine。它的设定是：一个系统可以重写自身的任意部分，但**只有当一个改写被证明能带来更高的期望效用时，改写才被允许执行**。可证明最优的自我改进——这是它的承诺，也是它的不可行之处：在真实系统里搜索这样的证明，成本高到完全没有工程价值。

但 Gödel Machine 留下的不是方案，而是一个判据：**自我改进必须经过独立于改进者自身的验证。** 模型觉得自己变好了不算数，得有外部的秤。

2025 年之后的几个工作，可以看作这个判据在工程上的不同实现。

[Darwin Gödel Machine](https://arxiv.org/abs/2505.22954)（Zhang 等，2025）是最直接的一个。它维护一个不断增长的 Agent 档案库，每轮从库里挑一个 Agent，让它用基座模型修改自己的代码，然后在 SWE-bench、Polyglot 这些基准上跑分；分数变好的新版本进入档案库，成为后续演化的父代。基座模型始终是冻结的，被改进的是围绕模型的脚手架：工具、工作流、自我调用的方式。它的名字里带 "Darwin" 是有意的——档案库保留了多样性，改进不沿单一路径爬坡，而是开放式地探索。

另一条线是 DeepMind 的 [AlphaEvolve](https://arxiv.org/abs/2506.13131)（2025）：用语言模型对代码做变异，用**自动化评估器**给每个变异体打分，种群式演化。它在矩阵乘法算法、数据中心调度这类问题上有真实产出——发现了 4×4 复数矩阵乘法的新算法（48 次标量乘法），改进了 Google 数据中心的调度效率。它演化的对象是被优化的代码而不是 Agent 自身，但结构是同一个：生成—验证—保留—继承。

更近的 [AIDE²](https://arxiv.org/abs/2609.26457) 则把这个结构推到了 AI 研究本身：做研究的 Agent，递归地改进"做研究的 Agent"。

![RSI：跨代际的自我改进循环](/images/posts/react-rsi/rsi-loop.svg)

把这些工作放在一起看，它们共享一个结构，也就是我理解的 RSI 的最低门槛：

1. **改动落在 Agent 自身**——代码、提示词、自身结构，而不是只落在当前任务的上下文里；
2. **由独立于生成者的验证裁决**——基准、自动评估器、环境反馈，而不是模型自我感觉良好；
3. **验证通过的改动被继承**——下一代从改动后的版本出发，而不是每次都从同一个起点重新跑。

Gödel Machine 要求的是"证明"，工程实现把它换成了"基准加档案库"。验证强度降了几个数量级，可行性才真正出现。这个妥协是重要的，后面会回来谈它的代价。

## 用三个问题把它们排成一条线

现在可以用开头的三个问题，把这条线上的代表工作放进同一张表里：

| 系统 | 改了什么 | 由谁验证 | 下一轮是否继承 |
| --- | --- | --- | --- |
| ReAct | 任务内的轨迹（上下文变长） | 环境观察（当轮生效） | 不继承，任务结束即清空 |
| Reflexion | 反思文本（情景记忆） | 同一任务的下一次尝试 | 任务内继承，跨任务不继承 |
| STOP | 改进方案的脚手架代码 | 下游任务性能 | 继承，且递归作用于改进器自身 |
| DGM / AlphaEvolve | Agent 自身的代码与结构 | 基准 / 自动评估器 | 继承，进入下一代 Agent |

这张表对我有两个用处。

第一，它是一条谱系，不是一条鄙视链。ReAct 在这张表里的位置并不低：它解决的问题——单次任务里如何让推理落地——至今仍是所有 Agent 的基本功。DGM 里那个自我修改的 Agent，执行任务时靠的依然是 ReAct 式的循环。层与层之间是依赖关系，不是替代关系。

第二，它让"滥用"变得可识别。一个词有没有被用对，不需要争论定义，问三个问题就行。改的只是上下文？那是一次任务的运行。验证来自模型自己的叙述？那只是自我感觉。下一轮从同一个起点重新出发？那什么都没有积累。**三个答案里有一个不对，叫 RSI 就是夸大。**

## 我的判断：RSI 的真实水位

表排完之后，可以说说我自己的看法了。

**被高估的，是上下文层的"改进"。** in-context learning、失败重试、反思记忆，这些当然有价值，但它们是推理技术，不是自我改进。2026 年大量打着 self-improving 旗号的系统，拆开看都是这一层。这类工作的真实贡献是把上下文工程做得更好，这没什么不好意思的——非要说成 RSI，反而模糊了它真正解决的问题。

**被低估的，是验证器。** 回看那张表，从 STOP 往右，每一行的分水岭都不在"模型会不会改自己"——今天的模型改代码、改提示词已经很熟练——而在"改动由谁裁决"。DGM 依赖 SWE-bench 这种有标准答案的基准，AlphaEvolve 依赖可以自动跑分的评估器。它们全都收敛在**验证便宜且可靠**的领域：代码、数学、有明确指标的工程问题。这不是巧合。没有便宜可靠的验证，递归改进就无法分辨"变好"和"看起来变好"，整个循环立刻退化成随机漂移甚至自我欺骗。我的判断是：**RSI 的瓶颈不在生成能力，在验证成本。**

由此可以推出三个工程上的真实难点。

一是**验证成本随代际线性甚至超线性增长**。每一代候选都要重新跑基准，DGM 的实验本身就很昂贵。验证越严格越贵，越便宜越容易被钻空子，这个张力不会消失。

二是**退化风险，尤其是 reward hacking**。一个有权修改自身代码的 Agent，和一个能被它触碰的评估器放在一起，演化压力早晚会找到"修改评估代码让分数变好"这条捷径。DGM 的论文里已经讨论了相应的防范（评估代码隔离、沙箱、人类审查），但我认为这会是所有 RSI 系统的长期标配，而不是可选项：**评估器必须是 Agent 不可修改的。**

三是**目标漂移**。Gödel Machine 用"证明"锁死了目标函数，工程实现用基准近似目标——基准只是目标的代理。经过几十代、几百代自我修改之后，系统优化的还是那个我们最初想要的东西吗？Goodhart 定律在多代自我改进里会被放大，因为每一代的微小偏移都会被继承和复利。

对未来的判断，我相对比较保守：**短期内，RSI 会停留在有自动验证器的窄域**——代码生成、算法发现、芯片设计、形式化数学。这些领域会出真实的成果，AlphaEvolve 已经证明了这一点。而开放式的、通用能力上的递归自我改进，卡的不是模型不够聪明，而是我们还没有为"通用地变好"造出一台秤。谁先解决便宜而可信的通用验证，谁才真正打开 RSI 的下一层。

## 什么才配叫自我改进

绕了一圈，回到"改进"这个词本身。

我现在愿意这样定义它：一次改进至少要同时满足三件事——**有变化**（系统的某个持久组成部分真的不一样了）、**有裁决**（这个不一样被独立于系统自身的标准判定为更好）、**有积累**（下一次运行的系统带着这个变化出生）。三者缺一，就只是运行，不是改进。

按这个标准，ReAct 是一次漂亮的运行，Reflexion 是任务内的进步，STOP 开始积累，DGM 和 AlphaEvolve 才是完整意义上的自我改进——尽管还只是窄域里的、有人看着的自我改进。

ReAct 教会了 Agent 在一次任务里思考；RSI 想做的是让 Agent 下一次"出生"时就比这一次强。前者已经基本解决了，后者才刚刚被证明可行，而且只在有秤的地方可行。把前者也算进后者，不会让后者更近，只会让我们看不见它到底还有多远。
